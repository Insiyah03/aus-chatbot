# AUS Catalog RAG Assistant

A local Retrieval-Augmented Generation (RAG) assistant for answering questions about the **American University of Sharjah (AUS) Undergraduate Catalog 2025–2026**.

The system retrieves relevant information from the catalog and uses a local Ollama language model to generate answers grounded in the retrieved content, with page citations back to the source PDF.

## Features

* Ask natural-language questions about courses, prerequisites, programs, scholarships, deadlines, and fees
* Hybrid retrieval combining:
  * Vector search (ChromaDB + `mxbai-embed-large`)
  * BM25 keyword search (strong on exact course codes like `COE 486`)
  * Reciprocal Rank Fusion to merge the two
* Local LLM generation using Ollama — no external API calls, no data leaving the machine
* Deterministic page citations, built from retrieved-chunk metadata rather than trusted from the model's own text
* Multi-turn conversational memory (follow-up questions like *"what about its prerequisites?"* work)
* Streamlit web interface with:
  * Model switcher (swap between `llama3.2`, `llama3.2:1b`, or a custom tag without touching code)
  * Retrieval method shown per source (BM25 / vector / both)
  * Live per-answer timing breakdown
  * A debug view of the actual retrieved excerpts used to ground each answer
  * Regenerate last answer / export conversation to Markdown

## Tech Stack

* **Python**
* **Streamlit** — web interface
* **Ollama** — local LLM runtime
* **ChromaDB** — vector store
* **mxbai-embed-large** — embeddings
* **llama3.2** — answer generation
* **rank-bm25** — keyword search

## How It Works

```text
AUS Catalog PDF
      ↓
Text & Table Extraction        (extract_pdf.py, extract_tables.py)
      ↓
Preprocessing & Chunking       (preprocess.py)
      ↓
Vector Index + BM25 Index      (build_index.py, build_bm25_index.py)
      ↓
Hybrid Search (RRF)            (hybrid_search.py)
      ↓
LLM Generation + Citations     (answer.py, llama3.2)
      ↓
Answer
```

## Setup

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd AUS_RAG_Assistant
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

Activate it on Windows:

```bash
venv\Scripts\activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Install Ollama

Install [Ollama](https://ollama.com/) and download the required models:

```bash
ollama pull mxbai-embed-large
ollama pull llama3.2
ollama pull llama3.2:1b    # optional — faster on CPU-only machines, some quality tradeoff
```

### 5. Build the pipeline

Run once (and again any time the source PDF changes):

```bash
python -m src.ingestion.preprocess
python -m src.embeddings.build_index
python -m src.retrieval.build_bm25_index
```

## Running the Assistant

From the project root, with `ollama serve` running:

```bash
streamlit run app.py
```

The Streamlit interface will open in your browser.

You can also query from the command line:

```bash
python -m src.generation.answer --query "What is COE 486?" --stream --timing
```

## Data

The assistant answers using only the **AUS Undergraduate Catalog 2025–2026** PDF in the `data` directory. All processed data and search indexes (`data/processed/`, `data/chroma_db/`, `data/bm25_index/`) are generated locally by the pipeline above — nothing is bundled with the repo.

## Status

Complete. The full pipeline — extraction, chunking, hybrid retrieval, local LLM generation with citations, and the Streamlit UI — is built and working end-to-end.

### Known limitations

* Curriculum-sequence tables aren't tagged with which major/program they belong to (needs an explicit page-range → major mapping to do reliably).
* Answer generation runs on CPU on this machine (no supported GPU acceleration for the current hardware/Ollama combination), so response time depends on hardware — `llama3.2:1b` is meaningfully faster than the default `llama3.2` if that matters more than answer quality for your use case.
* No "stop generation" control once an answer starts streaming.
